# 代码与模块说明

本文档回答三个问题：每个文件做什么、为什么需要它、复试时怎样解释。随着模块新增或行为改变，本文件必须同步更新。

## 一 当前执行链

```text
本地 ORL 图片
    ↓ load_orl：读取并检查
ORLDataset：统一保存图片、身份标签和路径
    ↓ audit_orl.py：汇总数据事实
results/audit/orl_summary.json：可追溯的审计结果
    ↓ tests/test_data.py：自动检查关键规则
pytest：报告代码是否仍满足预期
```

这一阶段还没有训练模型。当前代码只完成“确认数据可信”和“确认配对规模计算正确”，避免在错误数据上继续实验。

## 二 `src/face_verification/data.py`

### `ORLDataset`

一个不可随意改动的数据容器，同时保存：

- `images`：形状为“图片数 × 高 × 宽”的像素数组；当前 ORL 为 `400 × 112 × 92`。
- `labels`：每张图片对应的身份编号，例如 `s1` 被转换为整数 `1`。
- `paths`：每张图片的原始路径，用于追查某个实验样本来自哪里。

使用数据容器而不是返回三个松散变量，可以减少顺序放错和含义混淆。`frozen=True` 表示创建后不能重新给字段赋值，有助于防止实验过程中无意替换整批标签或图片。

### `ORLDataset.flattened`

把每张 `112 × 92` 的二维图片拉直成长度为 `10304` 的一维向量，最终得到 `400 × 10304` 的数据矩阵。PCA 和多数传统机器学习接口要求“每行一个样本、每列一个特征”，所以需要这一步。

它只改变数组形状，不删除信息，也不是 PCA 降维。

### `_numeric_suffix(path, prefix)`

从 `s10` 中取出 `10`，或从 `10.pgm` 中取出 `10`，用于按数字顺序排列目录和图片。如果直接按字符串排序，`s10` 可能排在 `s2` 前面。

函数名前的下划线表示它是模块内部辅助函数，不作为项目公开接口。

### `theoretical_pair_counts(num_people, images_per_person)`

计算完整数据在不区分先后顺序时能产生多少同一人配对和不同人配对。

- 同一人配对：每个人从自己的 `m` 张图中选两张，即 `m(m-1)/2`，再乘身份数。
- 不同人配对：先选两个不同身份，再从两个人各选一张图片。

对 ORL 而言结果是 1800 对正样本和 78000 对负样本。这个函数只计算理论规模，不负责真正抽样；后续会单独设计平衡、固定且无泄漏的配对模块。

### `load_orl(root, strict=True)`

读取本地 ORL 数据并执行审计：

1. 检查根目录存在。
2. 找到并按数字排列 `s1` 至 `s40`。
3. 检查每个身份有 10 张 `.pgm` 图片。
4. 将图片转成灰度并把像素从 `0—255` 缩放到 `0—1`。
5. 检查全部图片尺寸一致。
6. 返回 `ORLDataset`。

`strict=True` 用于正式实验，要求数据严格满足 ORL 的 40 人、每人 10 张、总形状 `400 × 112 × 92`。严格校验能让缺图、错目录或异常尺寸尽早报错，而不是悄悄污染模型结果。

## 三 `src/face_verification/__init__.py`

这是 Python 包的公开入口。它只导出 `ORLDataset`、`load_orl` 和 `theoretical_pair_counts`，让其他脚本明确知道哪些能力可以稳定调用。`__all__` 相当于公开功能清单，内部辅助函数 `_numeric_suffix` 不在其中。

## 四 `scripts/audit_orl.py`

这是可执行的数据审计脚本，而不是模型训练脚本。

- `parse_args()`：读取命令行参数。`--data-dir` 指定图片目录，`--output` 指定结果文件，因此脚本不依赖某一台电脑的绝对路径。
- `main()`：调用加载器，统计身份和图片数量，计算理论配对数，并把事实写成 JSON。
- `if __name__ == "__main__"`：保证直接运行脚本时执行 `main()`，被其他代码导入时不自动运行。

JSON 适合保存审计结果，因为它既能人工阅读，也能被后续脚本直接解析，避免从截图或讲稿中手抄数字。

## 五 `tests/test_data.py` 与 pytest

测试文件现在检查：

- ORL 的理论配对数是否稳定等于 `(1800, 78000)`。
- 身份数为 0 或每人不足 2 张时是否明确拒绝计算。

测试用 Python 标准库 `unittest` 写断言，同时由 pytest 统一发现和运行。两者并不冲突：`unittest` 提供测试类和断言，pytest 提供简洁的执行器、失败报告及后续扩展能力。

统一运行命令：

```bash
.venv/bin/python -m pytest -q
```

`-q` 表示精简输出。写出虚拟环境中 Python 的完整相对路径，是为了明确使用本项目环境中的 pytest，减少环境错位。

## 七 当前第三方工具为什么存在

- NumPy：用规则的数值数组存放图像，后续进行矩阵运算和 PCA。
- Pillow：读取 `.pgm` 图片并统一转成灰度格式。
- scikit-learn：后续调用经过验证的 PCA、逻辑回归、SVM、交叉验证和指标接口。科研贡献不要求重新发明这些基础算法，而在于问题定义、无泄漏协议、参数实验、公平比较和结果解释。
- SciPy：预留给距离、统计检验等科学计算。
- Matplotlib：从真实实验数据生成可复现学术图。
- pytest：自动验证代码规则，防止后续修改悄悄破坏已有结论。

## 八 当前阶段可能追问

### 为什么不直接开始训练

数据路径、身份标签、尺寸或配对数量一旦错误，后面的高准确率也没有意义。先完成自动审计，是把研究输入固定下来。

### 调接口还算科研吗

算，但接口本身不是贡献。我们复用可靠算法实现，把工作重点放在验证任务定义、数据隔离、配对协议、参数选择、公平对比、统计分析和高相似风险解释上。

### 测试通过是否说明模型正确

不说明。测试只能说明目前编码的规则按预期执行；模型是否有效必须由独立实验数据和评价指标回答。
