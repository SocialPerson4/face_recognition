# 代码与模块说明

本文档回答三个问题：每个文件做什么、为什么需要它、复试时怎样解释。随着模块新增或行为改变，本文件必须同步更新。

## 一 当前执行链

```text
本地 ORL 图片
    ↓ load_orl：读取并检查
ORLDataset：统一保存图片、身份标签和路径
    ↓ audit_orl.py：汇总数据事实
results/audit/orl_summary.json：可追溯的审计结果
    ↓ tests/test_data.py：自动检查关键规则
pytest：报告代码是否仍满足预期
```

这一阶段还没有训练模型。当前代码已经完成“确认数据可信”“冻结身份互斥划分”和“生成平衡配对”，避免在错误或泄漏的数据上继续实验。

## 二 `src/face_verification/data.py`

### `ORLDataset`

一个不可随意改动的数据容器，同时保存：

- `images`：形状为“图片数 × 高 × 宽”的像素数组；当前 ORL 为 `400 × 112 × 92`。
- `labels`：每张图片对应的身份编号，例如 `s1` 被转换为整数 `1`。
- `paths`：每张图片的原始路径，用于追查某个实验样本来自哪里。

使用数据容器而不是返回三个松散变量，可以减少顺序放错和含义混淆。`frozen=True` 表示创建后不能重新给字段赋值，有助于防止实验过程中无意替换整批标签或图片。

### `ORLDataset.flattened`

把每张 `112 × 92` 的二维图片拉直成长度为 `10304` 的一维向量，最终得到 `400 × 10304` 的数据矩阵。PCA 和多数传统机器学习接口要求“每行一个样本、每列一个特征”，所以需要这一步。

它只改变数组形状，不删除信息，也不是 PCA 降维。

### `_numeric_suffix(path, prefix)`

从 `s10` 中取出 `10`，或从 `10.pgm` 中取出 `10`，用于按数字顺序排列目录和图片。如果直接按字符串排序，`s10` 可能排在 `s2` 前面。

函数名前的下划线表示它是模块内部辅助函数，不作为项目公开接口。

### `theoretical_pair_counts(num_people, images_per_person)`

计算完整数据在不区分先后顺序时能产生多少同一人配对和不同人配对。

- 同一人配对：每个人从自己的 `m` 张图中选两张，即 `m(m-1)/2`，再乘身份数。
- 不同人配对：先选两个不同身份，再从两个人各选一张图片。

对 ORL 而言结果是 1800 对正样本和 78000 对负样本。这个函数只计算理论规模，不负责真正抽样；后续会单独设计平衡、固定且无泄漏的配对模块。

### `load_orl(root, strict=True)`

读取本地 ORL 数据并执行审计：

1. 检查根目录存在。
2. 找到并按数字排列 `s1` 至 `s40`。
3. 检查每个身份有 10 张 `.pgm` 图片。
4. 将图片转成灰度并把像素从 `0—255` 缩放到 `0—1`。
5. 检查全部图片尺寸一致。
6. 返回 `ORLDataset`。

`strict=True` 用于正式实验，要求数据严格满足 ORL 的 40 人、每人 10 张、总形状 `400 × 112 × 92`。严格校验能让缺图、错目录或异常尺寸尽早报错，而不是悄悄污染模型结果。

## 三 `src/face_verification/__init__.py`

这是 Python 包的公开入口。它只导出 `ORLDataset`、`load_orl` 和 `theoretical_pair_counts`，让其他脚本明确知道哪些能力可以稳定调用。`__all__` 相当于公开功能清单，内部辅助函数 `_numeric_suffix` 不在其中。

## 四 `scripts/audit_orl.py`

这是可执行的数据审计脚本，而不是模型训练脚本。

- `parse_args()`：读取命令行参数。`--data-dir` 指定图片目录，`--output` 指定结果文件，因此脚本不依赖某一台电脑的绝对路径。
- `main()`：调用加载器，统计身份和图片数量，计算理论配对数，并把事实写成 JSON。
- `if __name__ == "__main__"`：保证直接运行脚本时执行 `main()`，被其他代码导入时不自动运行。

JSON 适合保存审计结果，因为它既能人工阅读，也能被后续脚本直接解析，避免从截图或讲稿中手抄数字。

## 五 `tests/test_data.py` 与 pytest

测试文件现在检查：

- ORL 的理论配对数是否稳定等于 `(1800, 78000)`。
- 身份数为 0 或每人不足 2 张时是否明确拒绝计算。

测试用 Python 标准库 `unittest` 写断言，同时由 pytest 统一发现和运行。两者并不冲突：`unittest` 提供测试类和断言，pytest 提供简洁的执行器、失败报告及后续扩展能力。

统一运行命令：

```bash
.venv/bin/python -m pytest -q
```

`-q` 表示精简输出。写出虚拟环境中 Python 的完整相对路径，是为了明确使用本项目环境中的 pytest，减少环境错位。

## 八 当前阶段可能追问

### 为什么不直接开始训练

数据路径、身份标签、尺寸或配对数量一旦错误，后面的高准确率也没有意义。先完成自动审计，是把研究输入固定下来。

### 调接口还算科研吗

算，但接口本身不是贡献。我们复用可靠算法实现，把工作重点放在验证任务定义、数据隔离、配对协议、参数选择、公平对比、统计分析和高相似风险解释上。

### 测试通过是否说明模型正确

不说明。测试只能说明目前编码的规则按预期执行；模型是否有效必须由独立实验数据和评价指标回答。

## 九 `src/face_verification/protocol.py`

### `DatasetSplit`

保存训练、验证、测试各自的图片下标和身份编号。这里同时保存两种信息，是为了既能让程序快速索引图片，也能让人直接审计三个集合有没有身份重叠。

### `PairRecord`

表示一条验证样本：`left_index` 和 `right_index` 指向两张图片，`target=1` 表示同一人，`target=0` 表示不同人。代码始终要求左下标小于右下标，所以 `(3, 8)` 和 `(8, 3)` 不会被当成两条不同样本。

### `PairSet`

保存一组 `PairRecord`，并提供正样本数和负样本数统计。它的作用类似数据结构课程中的封装：调用者不需要每次重新理解内部列表，就能得到协议需要的统计量。

### `split_by_identity(...)`

先取得全部身份编号，再用固定随机种子打乱，分配 24 个身份到训练集、8 个到验证集、8 个到测试集。一个身份的 10 张图始终一起移动，因此三部分不仅图片不重叠，身份也不重叠。

没有直接调用普通 `train_test_split`，因为我们的分割对象不是 400 张彼此独立的图片，而是 40 个身份组。普通逐图随机划分会让同一个人同时出现在训练和测试中，回答的是较容易的“已见身份的新照片”问题；身份互斥回答更严格的“方法能否推广到未见身份”问题。

### `make_balanced_pairs(...)`

执行顺序如下：

1. 只接收某一个集合内部的图片下标。
2. 对每个身份枚举全部同一人组合，形成正样本。
3. 枚举不同身份之间的候选组合。
4. 用固定种子进行无放回抽样，取得与正样本相同数量的负样本。
5. 合并并随机打乱记录顺序。

“无放回”表示一条负样本最多抽到一次；“固定种子”表示相同输入可以重新得到完全相同的负样本。函数从一开始使用无序组合，因此没有自身配对、重复配对或反向重复。

## 十 `scripts/build_orl_protocol.py`

该脚本把研究协议变成真实文件，而不是只写在文字计划中。默认使用划分种子 `20260913`，再为训练、验证、测试使用不同的配对种子，避免三个阶段共享同一串随机选择过程。

脚本输出：

- `summary.json`：保存策略、种子、身份编号、图片数量和正负配对数量。
- `train_pairs.csv`：后续只用于拟合 PCA 与模型。
- `validation_pairs.csv`：后续只用于选择维数、模型参数和阈值。
- `test_pairs.csv`：在所有选择冻结后只用于最终评价。

CSV 每行保存图片下标、相对路径、两个身份和目标标签。使用相对路径是为了换一台电脑仍能读取，也避免把本机用户名等绝对路径写入仓库。

运行命令：

```bash

```

## 十二 `src/face_verification/metrics.py`

该模块规定所有候选模型共用的评价尺子。约定 `target=1` 表示同一人、`target=0` 表示不同人，分数越大越像同一人，`score >= threshold` 时系统接受。

### `VerificationRates`

保存一个阈值下的四种计数与派生指标：

- `true_accepts`：实际同一人且正确接受。
- `false_rejects`：实际同一人但错误拒绝。
- `false_accepts`：实际不同人但错误接受。
- `true_rejects`：实际不同人且正确拒绝。
- `fmr`：错误接受数除以负样本数。
- `fnmr`：错误拒绝数除以正样本数。
- `true_accept_rate`：本人正确通过比例，等于 `1-FNMR`。
- `accuracy`：全部配对中判断正确的比例。

### `_validated_inputs(...)`

统一检查标签和分数是否为一维、长度是否一致、分数是否有限，以及标签是否同时包含 0 和 1。它以下划线开头，表示仅供模块内部复用。提前拒绝 NaN、缺少某一类别等输入，可避免产生看似正常但实际无定义的指标。

### `rates_at_threshold(...)`

给定一个阈值，将每个分数转换为接受或拒绝，再数出四种结果并计算 FMR、FNMR、真正接受率和准确率。这是所有门禁工作点指标的基础。

### `select_threshold_at_fmr(...)`

枚举实际分数能够形成的候选阈值，只保留满足目标 FMR 的阈值，再优先选择 FNMR 最低者。若 FNMR 相同，优先 FMR 更低、阈值更严格者。默认目标为 1%，但必须使用验证数据选择，不能使用测试数据。

### `equal_error_rate(...)`

调用 scikit-learn 生成 ROC 工作点，找到 FMR 与 FNMR 穿越的位置并做线性插值。返回 EER 和对应阈值。插值表示真实交点可能位于两个离散分数阈值之间，因此结果是估计值而不是一定对应某条样本分数。

### `roc_auc(...)`

调用 scikit-learn 的 `roc_auc_score` 计算整体排序能力。输入必须是连续分数而不是提前截断后的 True/False，否则无法遍历阈值。

## 十三 `scripts/check_metrics.py`

使用四条人工合成配对检查指标，并保存 `results/audit/metric_sanity.json`。它包含完全分离和分数交叉两个例子，每个数都能人工核算。

该脚本只证明指标实现符合示例，不证明任何人脸模型有效。输出文件中的 `artifact_type` 和 `warning` 明确阻止把它误当成 ORL 实验结果。


## 十四 `tests/test_metrics.py`

测试覆盖：完美阈值、一个错误接受、完全分离 EER/AUC、交叉分数 EER/AUC、目标 FMR 阈值选择，以及标签缺类、NaN 分数和非法目标 FMR。当前项目总测试数从 6 增加到 12。

### 一次指标计算在代码里怎样流动

指标模块不读取图片，也不训练模型。任何模型只要交出两个长度相同的一维数组，就能使用同一把尺子：

```python
y_true = [1, 1, 0, 0]       # 数据集提供的真实关系
scores = [0.9, 0.7, 0.6, 0.2]  # 模型输出的同一人分数
```

调用顺序可以理解为：

```text
_validated_inputs
  → 检查长度、标签和非法数值
rates_at_threshold
  → 将 score >= threshold 变成接受
  → 数出四种结果
  → 计算 FMR、FNMR 和准确率
select_threshold_at_fmr
  → 尝试所有实际候选阈值
  → 保留满足 FMR 上限的阈值
  → 选择 FNMR 最低者
equal_error_rate / roc_auc
  → 使用连续分数评价阈值变化与总体排序
```

因此“统一评分尺子”是指距离模型、逻辑回归、线性 SVM 和 RBF-SVM 都把真实标签和连续分数交给这些相同函数，不能各写一套有利于自己的统计方法。

## 十五 `src/face_verification/features.py`

该模块完成第一批真实人脸分数所需的特征和距离计算。

### `image_matrix(images)`

把“图片数 × 高 × 宽”的图像数组整理成“图片数 × 像素数”的二维矩阵。ORL 的一张脸为 `112×92=10304` 个像素，因此 400 张图片对应 `400×10304`。

函数统一使用 `float64` 双精度进行 PCA 和距离运算，并检查空数据、维度不足、NaN 和无穷大。这里的拉直只改变排列方式，不是降维。

### `fit_pca(train_images, retained_variance=0.95)`

只接收训练图片并拟合 PCA。拟合主要学到两样东西：训练平均脸和训练数据变化最明显的若干方向。`0.95` 表示从最重要方向开始累加，直到解释方差首次达到 95%，所以它不是提前写死的维数。

在本次 240 张训练图片上，95% 规则自动得到 125 个主成分。这个 125 只是第一版基线结果，不能代替后续用身份互斥内层交叉验证搜索最合适的 `k`。

### `transform_images(model, images)`

使用已经学好的训练平均脸和主成分方向，把新图片投影成 PCA 坐标。它不能用验证图片重新计算方向，否则验证信息会反过来影响特征提取，造成泄漏。

代码按 PCA 的定义执行“减去训练均值，再与主成分方向做内积”。当前不使用 whitening（白化），因此没有强行把每个主成分缩放到同样方差；这样第一版基线保留了高方差方向原有的相对权重。

### `negative_euclidean_pair_scores(features, pairs)`

欧氏距离就是两张脸各维差值平方、相加后再开根号：

`distance = sqrt((x1_1-x2_1)^2 + ... + (x1_k-x2_k)^2)`。

距离越小代表越像，但项目指标统一要求“分数越大越像”，所以返回 `score=-distance`。例如距离 2 的分数是 -2，距离 10 的分数是 -10；因为 `-2>-10`，近的配对仍得到更高分。

## 十六 `scripts/run_orl_distance_baselines.py`

这是第一份使用真实 ORL 图片产生验证分数的实验脚本，比较两个同级基线：

- `raw_pixels`：直接在 10304 个原始像素上计算欧氏距离。
- `pca_95`：PCA 仅在 24 个训练身份的 240 张图片上拟合，再在 125 维 PCA 空间计算欧氏距离。

脚本沿用冻结的身份划分和配对种子，只生成训练集、验证集分数，不为测试配对计算成绩。每个模型在验证集上按 `FMR≤1%` 选择自己的阈值，并同时记录 EER、ROC-AUC、四格计数和逐配对分数。

输出目录 `results/experiments/orl_distance_baseline_seed_20260913/` 包含：

- `summary.json`：配置、维数、解释方差和汇总指标。
- `train_scores.csv`：2160 条训练配对的真实模型分数。
- `validation_scores.csv`：720 条验证配对的真实模型分数。

CSV 保存每对图片的下标、标签与两个模型的分数，后续可以据此复核指标和生成分数分布图，不需要从截图反推数据。

## 十七 `tests/test_features.py`

新增 5 项测试，检查图片拉直顺序、PCA 均值只来自传入的训练图片、近距离配对得到更高分、未使用占位行不会参与运算，以及非法输入会被拒绝。项目当前共 17 项测试通过。

“训练图片均值”测试特意构造数值极端的未见图片：如果未见图片参与 PCA 拟合，PCA 均值会发生明显改变。测试确认模型均值严格等于训练数据均值，以代码证据约束防泄漏规则。

## 十八 `make_identity_folds(...)`

该函数位于 `protocol.py`，负责在外层训练图片内部建立身份互斥交叉验证折。输入不是全部 400 张 ORL 图片，而是外层已经确定的 240 张训练图片下标。

它先取得这 240 张图片对应的 24 个身份，用固定种子打乱，再通过 `array_split` 分成五组。前四折各有 5 个验证身份，最后一折有 4 个；每一轮把其中一组作为折内验证身份，其余 19 或 20 个身份作为折内训练身份。

一个身份只担任一次折内验证身份。函数同时保存每折的身份编号和图片下标，便于自动检查训练与验证是否互斥。

## 十九 `fit_pca_components(...)`

与按累计方差停止的 `fit_pca` 不同，这个函数明确拟合固定数量的 PCA 主成分，用于比较候选 `k`。它检查 `k` 必须是正整数，而且不能超过“训练图片数与原特征数的较小值”。

粗搜索每折只拟合一次最大候选 180 维 PCA，然后从结果中截取前 `k` 列。因为 PCA 主成分按照解释方差从大到小排列，前 40 个方向本来就是前 180 个方向的前 40 个，这种复用不改变任何候选的含义。

## 二十 `scripts/search_orl_pca_k.py`

脚本执行 PCA 维数粗搜索：

```text
外层24个训练身份
  → 固定种子分成5个身份互斥折
  → 每折用19或20人拟合PCA
  → 剩余4或5人生成平衡验证配对
  → 依次截取 k=10,20,40,80,120,160,180
  → 计算负欧氏距离、EER、AUC和低FMR工作点
  → 汇总五折均值与样本标准差
```

外层验证身份和测试身份完全不进入脚本。每个折内的配对在比较不同 `k` 前就固定，因此所有候选面对同一套题目。

输出目录 `results/experiments/orl_pca_k_coarse_seed_20260913/` 包含：

- `fold_results.csv`：7 个维数 × 5 折，共 35 行原始结果。
- `summary.json`：折协议、汇总均值、样本标准差与粗排名。

`observed_best_k` 只是按预先规定的平均 EER 排序得到的观测最优点；粗搜索时不等于已冻结的最终维数。

## 二十三 `src/face_verification/selection.py`

该模块把一标准误差规则实现成可测试的程序，而不是实验结束后人工挑选一个喜欢的 `k`。

`select_k_one_standard_error(...)` 接收每个候选的 `k`、平均损失、标准差和折数。处理顺序为：

```text
找到平均EER最低候选
  → 标准误差 = 该候选标准差 / sqrt(折数)
  → 截止值 = 最低平均EER + 一个标准误差
  → 找到平均EER不超过截止值的全部候选
  → 返回其中最小的k
```

返回的 `OneStandardErrorResult` 同时保存观测最低点、最终选择、标准误差、截止值和全部合格候选，保证决定可以审计。

## 二十六 `absolute_pair_differences(...)`

该函数把两张80维 PCA人脸向量变成一条80维配对特征：逐维计算绝对差 `|z1-z2|`。绝对值保证 `(A,B)` 与 `(B,A)` 的输入完全相同，符合人脸验证关系的对称性。

距离基线把这80个差异通过平方和压成一个距离；分类器则保留80个差异，让程序学习“哪些主成分差异更重要”以及“怎样组合这些差异”。

## 二十七 `scripts/compare_orl_model_families.py`

该脚本固定 `k=80`，在相同五个身份互斥折上初筛四种模型：

- PCA距离：不使用配对标签学习权重，返回负欧氏距离。
- 逻辑回归：学习80个差异的线性加权和，再通过逻辑函数表示同一人倾向。
- 线性SVM：学习一张最大间隔线性分界超平面。
- RBF-SVM：通过RBF核形成非线性边界，可以表示局部而弯曲的分类区域。

每个折内先用训练身份拟合80维 PCA，再分别生成平衡训练配对和未见身份验证配对。学习型模型使用 `StandardScaler` 加分类器组成管线，保证标准化器只从训练配对学习。

脚本调用 scikit-learn 完成优化求解，项目代码负责特征构造、隔离协议、统一参数、分数方向、逐折记录和评价。调用成熟库不等于没有科研过程；研究问题在于管线设计、公平比较、参数规律和泛化证据。

受当前 NumPy与macOS Accelerate组合影响，库内部有限矩阵乘法可能发出伪溢出警告。脚本只在模型拟合和评分的局部范围关闭该类浮点警告，随后明确检查全部决策分数必须有限；真实 NaN或无穷大会立即终止实验。

输出目录 `results/experiments/orl_model_screening_k80_seed_20260913/` 包含：

- `fold_results.csv`：4种模型×5折的训练和验证指标。
- `validation_scores.csv`：每条折内验证配对在四个模型下的连续分数。
- `summary.json`：配置、身份协议、汇总均值与标准差。

## 二十八 四种模型最通俗的区别

假设每对脸有80项“差异体检指标”：

- 距离模型：把80项按固定方法合成总差异，不从答案学习。
- 逻辑回归：学习一套线性权重，输出同一人的连续倾向。
- 线性SVM：寻找一张尽可能远离两类困难样本的平面。
- RBF-SVM：允许边界弯曲，能处理复杂关系，但小样本下也更容易记住训练细节。

`C` 控制训练错误受到多重惩罚；RBF的 `gamma` 控制单个训练样本影响范围。当前 `C=1、gamma=scale` 只是初始值，不能据此完成最终模型比较。

## 三十 `src/face_verification/models.py`

该模块集中创建和训练分类器，防止不同实验脚本悄悄采用不同预处理。

`make_verification_classifier(...)` 根据模型家族返回 `StandardScaler + 分类器` 管线。标准化器和分类器在调用 `fit` 时按顺序只学习传入的训练配对。支持逻辑回归、线性核SVC和RBF核SVC，并拒绝非正数 `C/gamma`。

`fit_and_score_classifier(...)` 调用库完成拟合，再输出训练与验证的 `decision_function` 连续分数。当前NumPy与macOS数值库组合可能对有限矩阵乘法发出伪警告，函数只在该局部运算抑制警告，随后强制检查全部输出必须是有限值。

## 三十一 通用配置一标准误差选择器

`select_configuration_one_standard_error(...)` 位于 `selection.py`。调用者提供每个配置的平均损失、标准差和预注册复杂度键；函数返回观测最好下标、一个标准误差截止值、所有合格配置下标和复杂度最低的选择下标。

线性模型的复杂度键只有 `C`；RBF的键依次为 `gamma、C`。选择器不知道这些数字的业务含义，只严格执行实验在看结果前传入的排序规则。
